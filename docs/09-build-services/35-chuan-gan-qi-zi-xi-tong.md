# 传感器子系统

## 简介

传感器子系统为 OpenHarmony 设备提供各类物理传感器的数据采集与分发能力，包括运动传感器（加速度、陀螺仪）、环境传感器（光线、温度、气压、湿度）以及方位传感器（磁场、方向）等。它是 IoT、穿戴、车机、手机等设备的"感知入口"——没有传感器，设备就无法感知运动、环境变化与用户姿态。

## 支持的传感器类型

| 传感器 | 测量内容 | 典型用途 |
|--------|----------|----------|
| **加速度（Accelerometer）** | 三轴线性加速度 | 步数检测、屏幕旋转、摇晃手势 |
| **陀螺仪（Gyroscope）** | 三轴角速度 | 姿态跟踪、游戏体感、防抖补偿 |
| **环境光（AmbientLight）** | 光照强度 | 自动亮度调节、背光控制 |
| **磁场（Magnetic）** | 三轴磁场强度 | 电子罗盘、方向校准 |
| **气压（Barometer）** | 大气压强 | 海拔估算、天气监测 |
| **温度/湿度** | 环境温度与湿度 | 智能家居、气象监测 |
| **接近（Proximity）** | 物体距离 | 通话息屏、口袋检测 |
| **霍尔（Hall）** | 磁场变化 | 翻盖检测、皮套唤醒 |

> 具体可用传感器取决于硬件配置。IoT 设备可能只有加速度与温度；手机则通常配备全系列传感器。

## 整体架构

```
应用层（ArkTS / C++）
  │  @kit.SensorServiceKit
  ▼
传感器系统服务（Sensor Service SA）
  │  多路复用、采样率控制、事件分发、批处理
  ▼
传感器驱动（HDI）
  │  统一接口屏蔽芯片差异
  ▼
硬件层（传感器芯片 + MCU）
```

* **Sensor Service**：运行在用户态的系统服务，管理所有传感器的状态与订阅关系。它负责多应用共享同一传感器时的采样率折中、数据批处理（batching）与低功耗调度。
* **传感器 HDI**：硬件驱动接口，将不同厂商（如 Bosch、STMicro、InvenSense）的传感器驱动统一为标准化接口，使上层无需关心芯片寄存器细节。
* **硬件层**：包括 MEMS 加速度计、陀螺仪、环境光二极管、气压计等物理传感器，通过 I2C/SPI 与主控连接。

## 使用方式

```ts
import { sensor } from '@kit.SensorServiceKit';

// 订阅加速度数据，采样周期 100ms
sensor.on(sensor.SensorId.ACCELEROMETER, (data) => {
  console.info(`x=${data.x}, y=${data.y}, z=${data.z}`);
}, { interval: 100000000 }); // 单位：纳秒

// 取消订阅
sensor.off(sensor.SensorId.ACCELEROMETER);
```

### 订阅模型

传感器采用**发布-订阅**模型：

- 应用向 Sensor Service 注册订阅，指定传感器类型与期望采样率；
- Sensor Service 根据所有订阅者的需求，向驱动配置实际采样率（通常取最小公共倍数或最高频率）；
- 驱动采集数据后，通过回调或事件方式分发给订阅者；
- 当所有订阅者都取消后，Sensor Service 关闭驱动采集以节省功耗。

## 多应用复用与功耗优化

传感器是共享资源，多个应用同时订阅时，Sensor Service 会自动协调：

- **采样率折中**：若应用 A 需要 50Hz、应用 B 需要 100Hz，驱动以 100Hz 采集，向 A 做下采样；
- **批处理（Batching）**：低功耗场景下，驱动将多次采样缓存为一批，通过中断一次性上报，减少 CPU 唤醒次数；
- **按需开关**：无订阅时驱动完全关闭，避免空闲耗电。

## 校准与精度

传感器数据受温度、器件老化、安装姿态等影响，通常需要校准：

- **零点校准**：静止时采集基线，消除零偏误差；
- **尺度校准**：通过已知参考量（如重力加速度 9.8 m/s²）校正增益；
- **温度补偿**：部分高端传感器内置温度补偿算法，驱动可直接输出补偿后数据；
- **融合算法**：加速度 + 陀螺仪 + 磁场通过传感器融合算法（如 Mahony、EKF）输出更稳定的姿态角（pitch/roll/yaw）。

## 常见问题与排查

1. **订阅后无数据**：确认传感器在设备上存在（`sensor.getSensorList()` 查询）；检查权限是否申请。
2. **数据抖动大**：检查是否经过校准；高噪声传感器可降低采样率或做软件滤波。
3. **功耗高**：确认取消订阅是否及时；使用批处理模式降低唤醒频率。
4. **多应用冲突**：传感器服务会自动协调，但极端情况下某一应用要求过高频率会导致整体功耗上升。
