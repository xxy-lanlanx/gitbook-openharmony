## 三、统一章节模板（所有扩充按此结构，保证一致性）

每个子系统/技术章节套用：

1. **简介与读者对象**（50–100 字）
2. **在系统中的定位**（它解决什么问题、上下游是谁）
3. **整体架构**（必须配 1 张架构图，重绘为标准格式）
4. **核心概念 / 关键数据结构**（列出 3–8 个关键类型/接口签名）
5. **关键流程**（启动/调用/数据流，配 1 张时序或流程图）
6. **关键 API / 代码示例**（至少 1 段，标注版本与文件路径）
7. **典型问题与调试**（3–5 个常见坑 + 排查手段，呼应 DFX）
8. **与其他子系统的关系**（内部互链 ≥ 2 处）
9. **参考资源**（官方文档/源码路径/社区帖）

> 非子系统章节（01 学习、02 环境、03 工具、04 架构、10 启动等）可省略 4–6，但需保持"有图、有步骤、可操作"。
